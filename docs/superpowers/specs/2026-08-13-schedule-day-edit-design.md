# 스케줄표 하루 편집 설계

**한 줄 요약.** 달력 칸을 눌러 그 하루의 아빠·엄마 근무를 직접 고친다.

## 배경

스케줄표는 조회 전용이다(`ScheduleViewModel` 주석: "여기서 고치지 않는다"). 근무를 바꾸는 길은 **사진 → 인식 → 검수 → 저장**뿐이고, 그 경로는 한 달치를 통째로 다룬다. 하루가 틀렸을 때 고칠 방법이 배차표 사진을 다시 찍어 올리는 것밖에 없다.

엄마는 사정이 더하다. 엄마 근무는 저장된 레코드가 아니라 **패턴에서 계산돼 내려온다** — `DispatchShiftDay.slot`이 늘 nil인 것이 그 흔적이다. 패턴에서 벗어나는 날(대체근무·연차)을 넣을 자리가 아예 없다.

## 목표

- 달력에서 날짜 하나를 골라 아빠·엄마 근무를 고친다.
- 엄마 순번(`A`·`B`·`C`)을 넣고 달력에서 본다.
- 고친 결과가 달력에 곧바로 보인다.

## 비목표

- **삭제·되돌리기.** upsert만 둔다. 잘못 고친 날은 다시 눌러 바로잡는다.
- **엄마 배차표 사진 인식.** 이번에는 표시와 손입력 자리만 연다. 인식이 붙을 때 업로드 경로만 추가하면 되도록 조회 응답에 `slotCode`를 먼저 넣어 둔다.
- **메모(`note`) 편집.** 무인증 조회 응답에 그대로 실려 나가는 값이라 손입력을 열지 않는다.
- **여러 날 한 번에 고치기.** 그것이 필요한 경우가 곧 한 달치이고, 그 길은 사진이 이미 맡고 있다.

## 화면

### 진입

달력 칸을 탭하면 그날의 편집 시트가 뜬다. 툴바에 따로 「수정」 항목을 두거나 편집 모드를 켜게 하지 않는다 — 어느 날을 고칠지는 어차피 달력을 보고 정하므로, 눈으로 본 칸을 그대로 누르는 것이 가장 짧다.

**이번 달 칸만 연다.** 그리드 앞뒤 패딩(지난달·다음달 날짜)은 탭해도 아무 일이 일어나지 않는다. 화면에 보이는 달이 아닌 날짜를 고치면 저장한 뒤 그 결과가 어디에도 보이지 않는다.

기존 좌우 스와이프(달 이동)와 겹치지 않는다. `monthSwipe`는 `DragGesture(minimumDistance: 30)`이라 손가락이 30pt 넘게 움직여야 잡히고, 탭은 그 아래로 떨어진다. 다만 스와이프 제스처가 그리드 전체에 걸려 있으므로 **실기에서 칸 탭이 실제로 먹는지 확인한다.**

### 편집 시트

```
┌────────────────────────────────┐
│  2026년 8월 15일 (토) · 광복절  │
├────────────────────────────────┤
│  엄마                           │
│    [ 근무 ] [ 휴무 ]            │
│    순번   [ A ] [ B ] [ C ]     │
├────────────────────────────────┤
│  아빠                           │
│    [ 근무 ] [ 휴무 ]            │
│    순번   [ 1 ] [ 2 ]           │
├────────────────────────────────┤
│             [ 저장 ]            │
└────────────────────────────────┘
```

**역할을 먼저 고르게 하지 않는다.** 두 사람을 함께 보려고 여는 달력이라, 그날 화면에도 둘이 같이 있어야 한다.

**엄마가 위, 아빠가 아래.** 달력 칸의 밴드 순서와 같다(`ScheduleDayCellView`). 화면마다 순서가 뒤집히면 어느 밴드를 고치고 있는지 헷갈린다.

### 미등록이라는 세 번째 상태

데이터에는 근무·휴무 말고 **미등록**(레코드 없음)이 있다. 아빠 배차표를 아직 안 올린 달이 통째로 그 상태다.

미등록인 역할은 **근무/휴무 어느 쪽도 선택되지 않은 채로** 뜬다. 미등록을 휴무로 미리 칠해 두면, 엄마만 고치려고 연 시트에서 저장 한 번에 아빠의 그 달 첫 레코드가 「휴무」로 생겨 버린다. 사람이 고른 적 없는 값이다.

그래서 저장은 **사용자가 실제로 건드린 역할만** 보낸다. 손대지 않은 역할은 요청에 실리지 않고 서버에서도 건드려지지 않는다. 저장 버튼은 건드린 역할이 하나라도 있을 때 열린다.

### 순번

- **아빠**: `1`·`2` 중 하나. 고르지 않아도 된다.
- **엄마**: `A`·`B`·`C` 중 하나. 고르지 않아도 된다.

둘 다 자유 입력이 아니라 선택지다. 손으로 치게 두면 숫자가 아닌 값과 오타를 걸러 내는 검증이 따라붙는데, 실제로 쓰이는 값이 몇 개뿐이라 그 검증을 만들 이유가 없다.

**저장된 값이 선택지에 없으면 그 값도 함께 보여준다.** 사진 인식이 `3`을 넣어 둔 날을 열었을 때 선택이 비어 있으면, 휴무만 고치려던 저장이 순번을 조용히 지운다. 서버 검증은 `1`·`2`로 좁히지 않는다 — 사진 경로가 넣는 값을 앱 화면의 선택지가 정할 일이 아니다.
- **휴무를 고르면 순번 칸이 잠기고 값이 비워진다.** 휴무인데 순번이 남은 상태를 애초에 만들지 않는다. 서버도 같은 규칙을 적용한다 — 화면 한쪽에서만 막으면 다른 호출자가 모순된 값을 넣는다.

### 달력 표시

아빠 밴드는 지금처럼 `slot` 숫자를, 엄마 밴드는 `slotCode` 문자를 쓴다. **값이 있으면 쓰고 없으면 색만 칠한다** — 지금 아빠 밴드가 이미 그렇게 동작한다(`badge.slot.map(String.init) ?? " "`). 엄마 사진 인식이 나중에 붙어도 화면은 손대지 않는다.

접근성 문구도 같이 늘린다: `"엄마 A번 근무"`.

## API

### 하루 저장

```
PUT /dispatch/shifts/2026-08-15

{
  "father": { "working": true,  "slot": 3 },
  "mother": { "working": true,  "slotCode": "A" }
}
```

기존 `POST /dispatch/shifts`를 쓰지 않고 새로 낸다. 그쪽은 본문이 `{role, days[]}`라 **요청 하나에 역할이 하나**뿐이고, 한 시트에서 두 사람을 고치려면 두 번 호출해야 한다. 그 사이에 실패하면 아빠만 저장된 상태가 남고 뒷수습이 앱으로 넘어온다. 하루 편집은 URL에 날짜가 드러나는 `PUT` 한 방이 뜻에도 맞고, 사진 저장이 쓰는 계약을 건드리지 않는다.

**검증**

| 규칙 | 어겼을 때 |
|---|---|
| `father`·`mother` 둘 다 없음 | 400 |
| `mother`에 `slot` | 400 — 엄마 순번은 `slotCode`다 |
| `father`에 `slotCode` | 400 |
| `slotCode`가 `^[A-C]$`가 아님 | 400 |
| `slot`이 음수 | 400 |
| path 날짜가 `LocalDate`로 안 읽힘 | 400 |
| `working: false`인데 순번이 옴 | 오류가 아니라 **무시하고 `null`로 저장** |

`note`는 이 요청에 없다. 손입력을 열지 않기로 했고, **기존 값도 건드리지 않는다** — 사진에서 읽어 저장된 `note`가 하루 편집 한 번에 지워지면 안 된다.

**응답은 `204 No Content`다**

앱은 자기가 보낸 값을 이미 알고 있다. 안 보낸 역할은 서버도 건드리지 않으므로 그 칸은 화면에 그려진 그대로다. 그러니 응답 바디를 받아 봐야 방금 보낸 값과 안 바뀐 값뿐이다.

**성공하면 앱이 보낸 값으로 그 칸을 갈아 끼운다.** 달 전체 재조회도, 하루치 재조회도 없다.

갈아 끼울 값은 편집 시트가 만든다. 건드린 역할은 폼의 값으로, 손대지 않은 역할은 **시트를 열 때 받은 원본 그대로** 둔다. `note`도 원본을 지킨다 — 서버가 건드리지 않는 값이라 화면에서도 그대로여야 한다.

**두 역할은 한 트랜잭션이다.** 한쪽만 저장된 상태를 만들지 않으므로, 204를 받으면 보낸 것이 전부 들어갔다고 믿어도 된다.

서버가 값을 변형하는 자리는 하나뿐이다 — `working: false`인데 순번이 오면 `null`로 눕힌다. **앱은 휴무를 고르는 순간 순번을 비워 보내므로** 그 자리에 걸리지 않는다.

### 조회 응답 확장

`GET /dispatch/shifts?yearMonth=`의 각 날짜에 `slotCode: String?`를 더한다. 지금은 엄마 손입력에서만 값이 채워지고, 아빠는 늘 `null`이다.

## 서버 저장 모델

### 아빠

이미 날짜별 레코드다. 그 날짜를 upsert한다.

사진을 다시 올리면 그 달이 통째로 덮이므로 손으로 고친 날도 사진 값으로 돌아간다. upsert의 당연한 귀결이고, 잘못 고친 달을 통째로 되돌리는 수단이기도 하다.

### 엄마 — 레코드가 패턴을 이긴다 (조회는 이미 그렇게 동작한다)

엄마 근무는 패턴에서 계산되지만, **예외 레코드가 있으면 그것이 이기는 동작은 서버에 이미 있다** — `DispatchQueryService.findMonth`가 `storedByKey[MOTHER to date] ?: 패턴계산`으로 읽는다. `DispatchShift`의 문서도 "엄마는 패턴과 다른 날(예외)만 들어온다"고 적고 있다.

없는 것은 **그 레코드를 만드는 길**뿐이다. 지금 저장 경로(`POST /dispatch/shifts`)는 사진 검수에서만 불리고 아빠만 보낸다.

한 번 손대면 그 날짜는 계속 손입력값을 쓴다. 나중에 패턴이 바뀌어도 그 날은 따라가지 않는다 — **패턴으로 되돌리는 수단은 두지 않기로 했다.** 값 자체는 다시 눌러 고칠 수 있으므로 막히는 곳은 없다.

### 저장 위치

두 역할이 `dispatch_shift` 한 테이블을 이미 같이 쓴다. `(role, work_date)` 유일 제약도 있고 `findByRoleAndWorkDate`도 있어, upsert의 근거가 이미 갖춰져 있다.

더할 것은 `slot_code` 컬럼 하나다. `ddl-auto: update`라 nullable 컬럼 추가에 마이그레이션 파일이 따로 필요 없다.

### 인증

`GET /dispatch/shifts`만 무인증으로 열려 있다(`DispatchPublicEndpoints`). **`PUT`은 그 목록에 넣지 않는다** — 근무를 바꾸는 요청이 인증 없이 열리면 아무나 남의 달력을 고친다. 앱은 이미 인증 상태로 저장을 부르고 있어 앱 쪽에 추가로 할 일은 없다.

## 데이터 흐름

```
달력 칸 탭
  → 그 날짜의 현재 badge로 시트를 채운다 (없으면 선택 없음)
  → 사용자가 건드린 역할만 표시해 둔다
  → [저장] PUT /dispatch/shifts/2026-08-15  { 건드린 역할만 }
  → 204를 받으면 보낸 값 + 손대지 않은 원본으로 그 날짜 badge 교체, 시트 닫기
```

저장 뒤 아무것도 다시 조회하지 않는다. 보낸 것이 전부 들어갔음을 204가 보증한다.

「둘 다 휴무」 배경(`isBothOff`)도 같이 다시 계산해야 한다. 지금은 `load()`에서 한 번 만들고 마는 값이라, 하루를 고쳐 두 사람이 함께 쉬게 되어도 배경이 따라오지 않는다.

## 오류 처리

| 상황 | 화면 |
|---|---|
| 저장 실패 | **시트를 닫지 않는다.** 안에 오류 한 줄과 다시 시도. 달력은 건드리지 않는다 |
| 아무 역할도 안 건드림 | 저장 버튼 잠금 |
| 저장 중 화면을 떠남 | 요청은 그대로 두고 결과는 버린다. 다음 조회에 반영된다 |

순번이 선택지라 형식 오류가 생길 자리가 없다.

닫고 나서 실패를 알리면 어떤 값이 안 들어갔는지 다시 열어 확인해야 한다. 고치던 값이 그대로 남아 있는 자리에서 알리는 편이 짧다.

서버 메시지는 이미 사용자용 한국어다. 앱이 다시 쓰지 않되 봉투 JSON째 보여주지 않는다(`error.serverMessage`).

## 테스트

서버 테스트는 백엔드 스펙 문서에 있다.

**앱**

- `ScheduleDayEditViewModel`: 건드린 역할만 요청에 실린다 / 미등록인 역할은 선택 없음으로 시작한다 / 휴무를 고르면 순번이 비워진다 / 선택지에 없는 저장값(`3`)이 선택지에 함께 뜨고 저장에도 그대로 실린다 / 아무것도 안 건드리면 저장이 잠긴다
- `ScheduleDayEditViewModel`: 저장에 성공하면 손대지 않은 역할의 원본과 `note`가 그대로 남은 결과를 준다
- `ScheduleViewModel`: 저장 결과가 그 날짜 badge만 바꾼다 / 「둘 다 휴무」가 다시 계산된다 / 저장 실패가 달력을 바꾸지 않는다
- `ScheduleDayCellView`: `slotCode`가 있으면 엄마 밴드에 글자가, 없으면 색만 나온다
- 그리드 앞뒤 패딩 칸을 탭해도 시트가 열리지 않는다

## 열린 항목

- **칸 탭과 달 이동 스와이프.** 논리상 겹치지 않지만 실기에서 확인한다. 칸이 작아(76pt 높이) 손가락이 미세하게 움직이면 스와이프로 새는 경우가 있다.
- **엄마 순번 체계.** 지금은 `A`·`B`·`C` 셋으로 못 박는다. 실제로 `D`나 조 이름이 쓰이면 검증 정규식과 선택지를 함께 넓힌다.
