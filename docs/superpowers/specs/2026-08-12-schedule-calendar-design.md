# 스케줄표 설계

**한 줄 요약.** 배차 근무를 앱에서 달력으로 보고, 사진의 연월을 읽어 손입력을 없앤다.

## 배경

앱에는 배차 화면이 업로드와 검수 둘뿐이다. 사진을 올려 저장하고 나면 **저장된 결과를 앱에서 볼 방법이 없다.** 조회는 웹으로 하기로 했으나 웹 화면은 아직 없고, 등록이 제대로 됐는지 확인할 자리가 필요하다.

업로드 화면은 연월을 손으로 받는다(`2026-08`). 배차표 위에는 연월이 적혀 있고 **서버는 이미 그 값을 읽고 있다** — `DispatchVisionClient`가 첫 조각에서 `year`·`month`를 받아 오지만, 지금은 요청받은 연월과 비교해 `YEAR_MONTH_MISMATCH` 경고를 다는 데만 쓰고 값 자체는 버린다.

## 목표

- 앱에서 월 단위로 근무를 조회한다. 아빠와 엄마를 한 달력에 함께 본다.
- 사진에서 읽은 연월을 기준으로 삼는다. 업로드 화면에서 연월을 묻지 않는다.
- 읽지 못한 경우에도 막히지 않는다. 검수 화면에서 채운다.

## 비목표

- 웹 조회 화면. 별개 작업으로 남는다.
- 엄마 순번 입력. 지금처럼 빈 값으로 둔다.
- 달력에서 근무를 고치는 것. 수정은 사진 → 검수 경로로만 한다.

## 화면

### 진입과 이동

사이드 메뉴 항목 이름을 **배차표 등록 → 스케줄표**로 바꾼다. 진입하면 달력이 뜬다.

```
┌────────────────────────────────────────────┐
│  ‹    2026년 8월  ▾    ›        [사진 등록] │
├────────────────────────────────────────────┤
│  일   월   화   수   목   금   토           │
│  ...                                        │
└────────────────────────────────────────────┘
```

`‹` `›`로 한 달씩 이동한다. 세로 무한 스크롤이 아니라 **한 번에 한 달**이다 — 서버 조회가 월 단위(`GET /dispatch/shifts?yearMonth=`)라 화면 단위와 조회 단위가 같아진다.

연월 라벨을 누르면 기존 `MonthPickerSheet`가 그대로 뜬다. 지난 달을 확인하러 여러 번 누르는 것을 막는다.

오른쪽 위 **사진 등록**이 업로드 화면으로 들어가는 유일한 입구다.

### 칸 구성

기본 달력과 같은 순서로 쌓는다. 요일 머리글은 `WeekdayHeaderView`를 그대로 쓴다.

```
┌──────────┐
│ 15       │  날짜
│ ▁광복절▁ │  공휴일 — 기본 달력과 같은 연한 빨강 밴드
│ ██ 1 ███ │  아빠 — blue500, 흰 글자
│ ████████ │  엄마 — purple400, 순번이 없으면 글자 없음
└──────────┘
```

- **근무일에만 밴드를 그린다.** 휴무와 미등록은 둘 다 밴드가 없다. 아빠는 그 달 전체를 한 번에 등록하므로 미등록이면 달 전체가 비어 한눈에 보이고, 엄마는 패턴이라 늘 채워진다. 날짜 하나하나를 구분할 실익이 없다.
- 순번이 있으면 숫자를, 없으면 색만 칠한다. 엄마는 순번을 넣지 않으므로 늘 빈 밴드다.
- `note`는 달력에 쓰지 않는다. 무인증 응답에 실려 나가는 자유 입력이라 화면에 그대로 펼치지 않는다.
- 칸 높이는 64pt. 기본 달력의 120pt는 기록 이모지를 여러 줄 쌓기 위한 값이라 여기서는 남는다.

### 무엇을 같이 쓰고 무엇을 새로 만드나

그대로 쓰는 것: `WeekdayHeaderView`, `MonthPickerSheet`, `HolidayService`, `Color` 팔레트.

`CalendarView`와 `DayCellView`는 **건드리지 않는다.** 기록·파트너·과식·생일에 깊게 묶여 있어 일반화하려 들면 결함이 생길 자리만 늘어난다. 스케줄표는 자기 화면과 자기 셀을 가진다.

월 그리드 칸을 만드는 규칙(일요일 시작, 앞뒤 패딩, 셀 id)은 `CalendarViewModel.buildMonthData` 안에 있다. 이것만 `MonthGridBuilder`로 빼서 둘이 같이 쓴다. 순수 함수라 옮기는 위험이 낮고, `CalendarMonthTests`의 그리드 불변식 검증이 그대로 양쪽을 덮는다.

## 연월

### 지금의 순환

```
연월(앱이 보냄) → 저장된 줄 위치 조회 → 사진 읽기
```

줄 위치(`DispatchRoster`)는 성명 컬럼이 잘린 사진에서 순번이 어긋나지 않게 하는 장치다. 연월로 찾으므로 사진을 읽기 전에 연월이 필요하고, 그래서 앱이 먼저 알려주는 구조였다.

### 바꾸는 순서

첫 조각을 읽는 probe가 이미 연월을 준다. 순서만 바꾸면 순환이 풀린다.

```
사진 첫 조각 읽기(연월 포함) → 연월 확정 → 저장된 줄 위치 조회 → 나머지 조각
```

기준 연월은 이렇게 정한다.

| 요청 `yearMonth` | 사진에서 읽은 연월 | 기준 | 비고 |
|---|---|---|---|
| 있음 | 있음 | 요청값 | 다르면 `YEAR_MONTH_MISMATCH` (기존 그대로) |
| 있음 | 없음 | 요청값 | |
| 없음 | 있음 | 사진값 | 앱의 기본 경로 |
| 없음 | 없음 | **미상** | 응답 `yearMonth`가 `null` |

요청 `yearMonth`는 **선택**이 된다. 앱은 보내지 않는다. 웹이나 다른 호출자가 지정하고 싶을 때를 위해 자리는 남긴다.

### 연월을 못 읽는 사진

시간표만 잘라 찍은 사진에는 제목이 없다. 그리고 그게 하필 **줄 위치가 가장 필요한 사진**이다 — 성명 컬럼도 함께 잘려 있다.

연월을 모르면 **가장 최근에 저장된 줄 위치**를 쓴다. 잘린 변경분은 같은 달 배차표의 일부이므로 직전 기준이 맞다. 이때 `ROSTER_FROM_OTHER_MONTH` 경고를 달고, 검수 화면이 이렇게 옮긴다.

> 저장된 줄 위치를 다른 달 것으로 맞췄습니다. 순번이 밀리지 않았는지 사진과 대조해 주세요.

응답 `yearMonth`는 `null`로 나가고, 검수 화면 맨 위 칸이 빈 채로 뜬다. **연월을 채우기 전에는 저장 버튼이 잠긴다.**

### 검수 화면의 연월 칸

읽은 경우에도 칸은 보이고 고칠 수 있다. 사진과 나란히 놓고 확인하는 자리가 여기다.

형식은 `2026-08`이고 검증은 지금 업로드 화면이 쓰는 정규식(`^[0-9]{4}-(0[1-9]|1[0-2])$`)을 그대로 옮긴다. 서버 `YearMonth` 파싱은 `2026-3`에 400을 낸다.

저장 요청의 `date`는 **검수 화면에서 확정된 연월**로 만든다(`2026-08-01`).

### 줄 위치를 새로 저장하는 조건

지금은 `matchedBy == NAME && warnings.isEmpty()`일 때만 갱신한다. 여기에 **기준 연월이 미상이 아닐 것**을 더한다. 연월을 모르면 어느 달의 기준인지 적을 수 없다.

## 데이터 흐름

### 조회

```
ScheduleView 진입 / ‹ › 이동
  → ScheduleViewModel.load(yearMonth)
      GET /dispatch/shifts?yearMonth=2026-08   (무인증)
      GET /holidays?year=2026                  (연 단위, 캐시)
  → 월 그리드 렌더
```

공휴일은 **연 단위로 캐시하고 달을 옮길 때 되채운다.** 받은 값을 화면 상태 안에만 두고 「이미 받았다」는 표시를 바깥에 따로 두면 둘이 어긋난다 — 기본 달력에서 실제로 그렇게 되어 공휴일이 통째로 사라진 적이 있다(#70).

### 등록

```
[사진 등록] → 업로드(연월 안 물음) → 인식 → 검수(연월 확인·수정) → 저장
  → 달력으로 돌아와 그 달을 다시 조회
```

저장 후 돌아왔을 때 다시 조회하지 않으면 방금 넣은 것이 안 보인다. 이 화면의 목적이 그 확인이다.

## 오류 처리

| 상황 | 화면 |
|---|---|
| 근무 조회 실패 | 달력은 그리고 상단에 오류 한 줄. 다시 시도 버튼 |
| 공휴일 조회 실패 | 조용히 넘어간다. 근무가 주 정보고 공휴일은 부가다 |
| 인식이 연월을 못 읽음 | 검수 화면 연월 칸이 빈 채로 뜨고 저장이 잠긴다 |
| 줄 위치를 다른 달에서 가져옴 | 검수 화면에 `ROSTER_FROM_OTHER_MONTH` 경고 |
| 연월 형식 오류 | 칸 아래 안내, 저장 잠금 |

서버 메시지는 이미 사용자용 한국어다. 앱이 다시 쓰지 않되 봉투 JSON째 보여주지 않는다(`error.serverMessage`).

## 테스트

**서버**
- 요청 연월 없이 사진 연월만 있을 때 그 값이 기준이 된다
- 요청 연월이 있으면 사진 연월과 달라도 요청값이 기준이고 경고가 붙는다
- 둘 다 없으면 응답 `yearMonth`가 `null`이고 최근 줄 위치를 쓴다
- 기준 연월이 미상이면 줄 위치를 갱신하지 않는다
- 기준 연월이 미상일 때 32일 같은 값이 걸러진다

**앱**
- `ScheduleViewModel`: 달 이동이 그 달을 조회한다 / 응답이 날짜별·역할별로 갈린다 / 늦게 온 이전 달 응답을 버린다(generation)
- 공휴일 캐시: 달을 옮겼다 돌아와도 공휴일이 남는다
- `MonthGridBuilder`: 기존 그리드 불변식이 그대로 통과한다
- `DispatchReviewViewModel`: 연월이 비면 저장이 잠긴다 / 형식이 틀리면 잠긴다 / 저장 `date`가 확정 연월로 만들어진다

**엄마 패턴**은 서버가 계산해 내려주므로 앱은 그리기만 한다. 패턴 자체의 검증은 서버 쪽에 이미 있다.

## 열린 항목

- **아빠·엄마 색.** blue500 / purple400으로 시작한다. 실물에서 구분이 약하면 조정한다.
- **10MB 상한.** 실제 사진으로 재 보지 않았다. 이번 작업과 무관하게 남아 있는 확인 항목이다.
