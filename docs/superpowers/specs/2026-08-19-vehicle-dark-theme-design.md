# 차량 화면 다크 테마·24시간 타임라인·평균 주행거리 설계

**한 줄 요약.** 상태 타임라인을 7일 격자에서 **지금부터 거꾸로 24시간 한 줄**로 바꾸고, 주행 타일의 「이번 달·올해」를 **월·연 평균**으로 바꾸고, 차량 미니앱과 거기서 열리는 충전 화면을 **다크 테마**로 뒤집는다.

**앞선 작업:** `docs/superpowers/specs/2026-08-19-vehicle-state-timeline-design.md`의 4단계가 `main`에 있다(`6222662`). 이 설계는 그 위에서 시작하는 **5단계**이며, 4단계가 세운 결정 몇 개를 명시적으로 뒤집는다(아래 「뒤집는 결정」).

**서버 설계:** `../toy-back/docs/superpowers/specs/2026-08-19-tesla-state-timeline-drive-stats-design.md` — **개정판**(`154595a`). 초판은 이미 구현돼 있고(`0e2b8a9`) 이 개정에 맞춰 다시 구현된다.

## 배경

4단계를 실기로 보고 세 가지가 드러났다.

**7일은 너무 길다.** 타임라인이 답하려던 질문은 「어제 얼마나 깨어 있었나」·「밤새 충전이 언제 걸렸나」인데, 7일 격자에서 한 행은 화면 폭의 1/7이라 밤새 충전 한 건이 손톱만 하게 찍힌다. 실측상 최근 7일 구간이 168개인데 그것이 7행에 흩어지면 어느 행도 읽히지 않는다. **24시간을 한 줄로 쓰면 같은 폭에 22개만 놓인다** — 구간 하나가 7배 넓어진다.

**「이번 달·올해」는 시점에 끌려다닌다.** 매달 1일에 0으로 떨어지고 12월에 가장 커진다. 그 숫자로는 「내가 얼마나 타는 사람인가」를 알 수 없다. 평균은 시점과 무관하다.

**밝은 화면은 차 안에서 눈이 부시다.** 이 미니앱은 주차장·야간 주행 직후처럼 어두운 데서 열리는 일이 많다. 나머지 미니앱(가계부·식단·일정)은 책상에서 보는 것이라 사정이 다르다.

## 목표

- 최근 24시간을 한 줄로 읽는다. 오른쪽 끝이 「지금」이다.
- 「한 달에 얼마나, 일 년에 얼마나 타는가」를 시점과 무관한 숫자로 본다.
- 차량 미니앱과 거기서 열리는 충전 화면이 어두운 곳에서 편하게 읽힌다.
- 다른 미니앱은 **한 픽셀도 바뀌지 않는다.**

## 비목표

- 앱 전체를 다크로 만들지 않는다. 이 설계의 범위는 차량 미니앱 세 탭과 거기서 열리는 충전 상세·금액 입력 큐뿐이다.
- 라이트/다크 **토글**을 만들지 않는다. 차량 화면은 늘 어둡다.
- 시스템 다크 모드(`ColorScheme`)를 따라가지 않는다. 이 저장소의 색은 전부 고정 RGB라 시스템 설정에 반응하지 않고, 반응하게 만드는 것은 이 설계의 몫이 아니다.
- Swift Charts를 들이지 않는다. 손그림 관례 그대로다.

## 실측 (2026-08-19)

| 항목 | 값 |
|---|---|
| 최근 **24시간** 구간 | 상태 21 · 주행 1 · 충전 0 = **22개** (최근 7일은 168개였다) |
| 주행 전 기간 | 2021-09-03 ~ 2026-08-18, **107,257.8 km**, 5,057건 |
| 주행 기록이 있는 달 | **60개월** (빈 달 없음) |
| → 월 평균 | **1,787.6 km** |
| → 연 평균 | **21,451.6 km** |
| 다크로 바꿀 파일 | **18개**, 색 참조 **160곳** |
| `GlassCard`·`glassScreenBackground` 사용처 | 앱 전체 **56 파일** 중 차량·충전은 **16개** |

마지막 줄이 이 설계의 가장 큰 제약이다 — **공유 컴포넌트를 어둡게 뒤집으면 가계부·식단·일정이 함께 어두워진다.**

# A단계 — 24시간 타임라인과 평균 타일

다크와 무관하고 서로도 독립이다. 서버 계약이 바뀌므로 먼저 한다.

## 24시간 한 줄 타임라인

```
┌─ 최근 24시간 ──────────────────────────┐
│                                        │
│  ░░░░▓▓▒▒░░░░░░░░░░████░░░░▓▓░░░░▓▓▓  │
│  13시    19시    1시    7시   13시 지금 │
│                                        │
│  ▓온라인 ░오프라인 ▨잠자는중 ▒주행 █충전 │
└────────────────────────────────────────┘
```

- **한 줄이다.** 높이 24pt(7일 격자의 14pt보다 두껍다 — 행이 하나뿐이니 쓸 수 있는 세로가 늘었다).
- **오른쪽 끝이 「지금」이다.** 서버가 `to`를 요청 시각으로 주고 자정에 맞추지 않는다.
- 눈금은 **절대 시각**이다(「-12시간」이 아니라 「1시」). 답하려는 질문이 「밤새 충전이 **언제** 걸렸나」이므로 상대 시각으로는 못 읽는다. 4시간 간격으로 찍고 오른쪽 끝만 「지금」이라 적는다.
- 겹치는 순서는 4단계 그대로다: **상태를 깔고 → 주행 → 충전**.
- **최소 폭을 두지 않는다.** 1픽셀 하한만 둔다 — 4단계의 판례 그대로이고, 한 줄이 되면서 같은 구간이 7배 넓어졌으므로 근거가 더 강해졌다.

### 계산이 단순해진다

4단계의 `StateTimelineMath`가 하던 세 가지 중 **하나가 통째로 사라진다.**

| | 4단계 | 5단계 |
|---|---|---|
| 자정을 넘는 구간을 날짜 행으로 쪼갠다 | 있음 | **없앤다** — 행이 하나뿐이다 |
| 범위 밖을 자른다 | 있음 | 그대로 |
| `kind` 순으로 정렬한다 | 있음 | 그대로 |

`TimelineBar`에서 `dayIndex`가 사라지고 `start`·`end`는 **범위 전체에 대한 비율**이 된다.

```swift
struct TimelineBar: Equatable {
    let start: Double   // 0.0 = from, 1.0 = to
    let end: Double
    let kind: TimelineKind
}

enum StateTimelineMath {
    static func bars(_ response: StateTimelineResponse) -> [TimelineBar]
}
```

**자정 분할 테스트 셋(하루 안·자정 넘김·이틀 통과)은 지운다.** 그 코드가 없어지므로 남겨 두면 없는 것을 지키는 테스트가 된다. 범위 절단·정렬·빈 입력·모르는 상태·길이 0 테스트는 남는다.

### VoiceOver

행이 하나이므로 4단계의 「하루가 한 정거장」 규칙이 「**띠 전체가 한 정거장**」이 된다. 상태별 시간과 주행·충전 횟수를 한 문장으로 읽는다 — 「최근 24시간, 오프라인 18.2시간, 온라인 5.8시간, 주행 1회」. 4단계가 고친 규칙(온라인만 읽으면 온종일 오프라인인 날이 「기록 없음」이 된다)은 그대로 지킨다.

## 평균 타일

```
┌────────┬────────┬─────────┐
│  138   │ 1,788  │ 21,452  │
│  km/h  │   km   │   km    │
│ 역대 최고 │ 월 평균 │ 연 평균  │
└────────┴────────┴─────────┘
```

라벨만 바뀌는 것이 아니라 **서버 계약과 계산이 바뀐다.**

```swift
// DriveInsightsResponse — 4단계의 monthDistanceKm/yearDistanceKm를 대체한다
let totalDistanceKm: Decimal?   // 전 기간 총 주행거리
let recordedMonths: Int?        // 주행 기록이 있는 달 수 = 평균의 분모
```

**나눗셈은 앱이 한다.** 서버가 평균을 내 버리면 분모의 정의가 응답에서 사라진다 — 이 저장소가 단가·전비를 다루는 방식과 같다.

```swift
extension VehicleMath {
    /// 월 평균 = 총거리 / 기록이 있는 달 수. **분모가 0이거나 없으면 nil이다.**
    static func avgMonthlyDistanceKm(totalKm: Decimal?, months: Int?) -> Decimal?
    /// 연 평균 = 월 평균 × 12.
    static func avgYearlyDistanceKm(totalKm: Decimal?, months: Int?) -> Decimal?
}
```

**분모 0을 앱이 막는다.** 서버는 주행이 하나도 없으면 `recordedMonths: 0`을 그대로 낸다(1로 보정하지 않는다). 앱이 나누기 전에 걸러 `nil`을 내고, 타일은 `—`를 찍는다.

**「역대 최고」는 그대로다.** 세 칸 모두 기간 칩(`months`)을 따르지 않는다는 4단계 결정도 그대로이므로, 카드는 계속 기간 분기 **위에** 그린다.

**옵셔널로 받는 이유도 그대로다** — 서버가 개정 전 필드를 내는 동안 앱이 무너지지 않아야 한다. 셋 다 nil이면 카드째 감춘다(`showsStats`).

# B단계 — 다크 테마

## 팔레트

배경은 거의 검정에 아주 옅은 푸른 기, 카드는 **흰색 몇 %짜리 반투명 판**, 강조는 **민트**다. 경고·위험만 iOS 표준 색을 쓴다.

```swift
/// 차량 미니앱 전용 색. **`Color+Extensions.swift`의 밝은 팔레트와 섞어 쓰지 않는다** —
/// 한 화면에 두 체계가 섞이면 어느 쪽도 일관되지 않는다.
enum VehicleTheme {
    // 바탕
    static let background   = Color(red: 0.043, green: 0.047, blue: 0.055) // #0b0c0e
    static let surface      = Color(red: 0.078, green: 0.086, blue: 0.098) // #141619
    static let surfaceTint  = Color(red: 0.043, green: 0.075, blue: 0.149) // #0b1326 남색 기

    // 카드 — 채움이 아주 옅고 테두리가 형태를 만든다
    static let cardFill     = Color.white.opacity(0.04)
    static let cardStroke   = Color.white.opacity(0.18)

    // 강조
    static let accent       = Color(red: 0.176, green: 0.831, blue: 0.749) // #2dd4bf
    static let accentBright = Color(red: 0.369, green: 0.918, blue: 0.831) // #5eead4
    static let accentGlow   = Color(red: 0.306, green: 0.871, blue: 0.639) // #4edea3

    // 글자
    static let textPrimary   = Color(red: 0.933, green: 0.945, blue: 0.957) // #eef1f4
    static let textSecondary = Color(red: 0.855, green: 0.886, blue: 0.992) // #dae2fd
    static let textTertiary  = Color.white.opacity(0.40)

    // 상태
    static let warning = Color(red: 1.0, green: 0.808, blue: 0.0)   // #ffce00
    static let danger  = Color(red: 1.0, green: 0.231, blue: 0.188) // #ff3b30
}
```

**색 이름을 역할로 짓는다.** `slate500` 같은 밝기 번호가 아니라 `textSecondary`·`cardStroke`다. 이 층은 팔레트가 아니라 **의미의 사전**이어야 하고, 그래야 160곳을 옮길 때 「어떤 회색이었지」가 아니라 「무슨 역할이었지」로 옮길 수 있다.

## 적용 방식 — 환경값

`GlassCard`와 `GlassBackground`가 환경값을 읽는다. 차량 화면 루트에서 한 번 켜면 그 아래 전부가 따라온다.

```swift
extension EnvironmentValues {
    /// 차량 미니앱 다크 테마. **기본값은 false이므로 다른 미니앱은 아무 영향이 없다.**
    @Entry var vehicleDark: Bool = false
}
```

| 안 | 방식 | 왜 이것이 아닌가 |
|---|---|---|
| **환경값 (채택)** | 루트에서 한 줄, 카드가 읽는다 | — |
| 전용 컴포넌트 | `VehicleCard`를 따로 만든다 | 카드 구조가 둘로 갈라져 한쪽만 고치는 사고가 난다 |
| 파라미터 | `GlassCard(style: .dark)` | 호출부 16곳마다 인자를 붙여야 하고, 중첩 카드가 상속받지 못한다 |

**공유 컴포넌트 둘을 건드리는 것이 이 선택의 대가다.** 기본값이 `false`이고 그 갈래가 지금 코드와 완전히 같으므로 다른 55개 파일의 렌더 결과는 바뀌지 않는다. 그 사실을 지키는 것이 이 단계 리뷰의 첫 항목이다.

### 다크에서는 `glassEffect`를 쓰지 않는다

`GlassCard`는 지금 `.glassEffect(.regular, in:)`으로 그린다. 다크 갈래에서는 **`cardFill` + `cardStroke`로 명시적으로 그린다.**

Liquid Glass의 굴절·번짐은 뒤에 밝은 것이 있을 때 드러나는 효과다. 거의 검은 배경 위에서는 보이는 것이 거의 없으면서 색만 예측하기 어려워진다. 팔레트가 요구하는 값(흰색 4%, 테두리 18%)은 명확하므로 그대로 칠하는 편이 정직하다.

**이것은 이 저장소의 Liquid Glass 관례에서 벗어나는 결정이다.** 벗어나는 범위를 차량·충전 화면으로 못 박고, 다른 미니앱은 계속 `glassEffect`를 쓴다.

## 강조를 다시 세운다

4단계는 **「진한 패널이 화면에서 유일하다」**로 `BatteryNowCard`를 강조했다. 배경이 검정이 되면 그 장치가 통째로 무너진다 — 어두운 판이 더 이상 특별하지 않다.

강조를 **민트 링과 글로우**로 옮긴다.

- 잔량 링을 `accent`(민트)로 그리고, 링 뒤에 `accentGlow`를 흐린 그림자로 깐다. 화면에서 빛나는 것은 이것 하나뿐이다.
- 카드 배경은 다른 카드와 같은 `cardFill`을 쓴다. **더 이상 남색 그라디언트 패널이 아니다** — `batteryPanelBackground()`와 `BatteryPanelBackground`는 사라진다.
- 잔량 색 구간(`BatteryBand`)은 유지하되 값이 바뀐다: 높음 `accent`, 중간 `warning`, 낮음 `danger`. 판정 규칙(50/20 경계, 화면에 찍는 값으로 판정)은 그대로다.
- 열화 색 구간(`HealthBand`)도 같은 축으로: 좋음 `accent`, 보통 `warning`, 낮음 `danger`.

## 범위

**바꾼다:**

- `WooriHaru/Views/Vehicle/` 전부 — 세 탭과 그 카드들
- `WooriHaru/Views/Charge/ChargeDetailView.swift`, `ChargeRow.swift`, `ChargeCurveChart.swift`
- `WooriHaru/Views/Vehicle/ChargeCostQueueView.swift`

**건드리지 않는다:**

- 다른 미니앱 전부. `Color+Extensions.swift`의 기존 토큰은 **하나도 지우지 않는다** — 55개 파일이 쓰고 있다.
- `GlassTokens`(모서리·여백)는 그대로 쓴다. 어두워지는 것은 색이지 치수가 아니다.

## 뒤집는 결정

4단계 설계가 못 박았던 것 중 셋이 이 단계에서 무효가 된다. **문서를 고치지 않고 여기 적어 두는 이유는, 4단계 문서가 그때 무엇을 왜 정했는지의 기록이기 때문이다.**

| 4단계 | 5단계 |
|---|---|
| 「앱 전체를 다크로 뒤집지 않는다. 진한 패널은 여전히 화면에서 하나뿐이다」 | 차량·충전 화면은 다크가 된다. 진한 패널이라는 개념 자체가 사라진다 |
| 「진한 패널은 화면에서 하나뿐이다. 링도 하나뿐이다」 | 링 하나는 **유지한다.** 패널 규칙만 사라지고, 강조는 민트 글로우가 맡는다 |
| 「색은 기존 토큰만 쓴다. 새 토큰을 만들지 않는다」 | `VehicleTheme`을 새로 둔다. 기존 토큰은 남기되 차량 화면이 쓰지 않는다 |
| 「7행, 위가 가장 오래된 날, 아래가 오늘」 | 한 줄, 오른쪽 끝이 지금 |
| 「이번 달·올해」 | 월 평균·연 평균 |

## 경계와 오류

| 상황 | 화면 |
|---|---|
| `recordedMonths`가 0 또는 nil | 평균 두 칸이 `—`. 「역대 최고」는 있으면 그린다 |
| `totalDistanceKm`이 nil (구 서버) | 셋 다 nil이면 카드째 감춘다 |
| 타임라인 구간이 하나도 없음 | 「최근 24시간 기록이 없어요」. 못 받은 것과 다르게 그린다 |
| 타임라인 404 | 조용히 넘긴다. 4단계 결정 그대로다 |
| 값이 있는 새로고침 실패 | 있던 값을 그대로 두고 한 줄 배너. 4단계 결정 그대로다 |
| 다크 갈래에서 `glassEffect`가 없는 카드 | 테두리(`cardStroke`)가 형태를 만든다 — 채움만으로는 배경과 안 갈린다 |

## 테스트

Swift Testing. 뷰는 테스트하지 않고 계산과 뷰모델만 본다.

**`StateTimelineMath.bars`** — 4단계 테스트에서 자정 분할 셋을 지우고 나머지를 좌표 기준으로 고친다.

- 범위 한가운데 구간이 올바른 비율로 나온다
- `from` 이전·`to` 이후로 삐져나온 구간이 잘린다
- 마지막 구간이 `to`에서 끝난다(오른쪽 끝 = 지금)
- 빈 입력, 모르는 상태, 길이 0
- 상태 → 주행 → 충전 순 정렬

**`VehicleMath.avgMonthlyDistanceKm` / `avgYearlyDistanceKm`**

- 실측값으로 확인한다: `107257.8 / 60` → 월 1,787.6, 연 21,451.6
- **`months == 0`이면 nil** (0으로 나누지 않는다)
- `months == nil`이면 nil, `totalKm == nil`이면 nil
- 연 평균이 월 평균의 정확히 12배다

**`VehicleTheme`** — 색은 테스트하지 않는다. 대신 **다른 미니앱이 안 바뀌었는지**를 지키는 것은 리뷰의 몫이다(`vehicleDark` 기본값이 `false`이고 그 갈래가 기존 코드와 동일한지).
