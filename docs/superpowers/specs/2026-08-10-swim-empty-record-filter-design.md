# 수영 기록 — 내역 없는 기록 감추기 설계

작성일: 2026-08-10
짝 저장소: 없음 — **서버 작업이 없다.** 건강 앱에서 읽어 온 것을 거르는 일이다.

## 배경

애플워치 운동 앱에서 수영을 **잘못 시작했다가 바로 끝낸 기록**이 건강 앱에 그대로 남는다.
몇 초짜리에 거리도 없는 이 기록이 「수영 기록」 목록에 정상 기록과 나란히 카드로 뜬다.

```
2026년 8월 9일 (일)          오전 6:12 ~ 오전 6:12
📏 -    ⏱ 1분 미만
수영장 · 25m 레인
```

**거리 자리가 `-`뿐인 카드**다. 사용자가 지우려면 건강 앱까지 들어가야 하는데, 목록에서 안
보이게 하는 것으로 충분하다. 앱은 읽기 전용이므로 **지우지 않고 감춘다.**

---

## 무엇을 감추나

**거리도 스트로크도 0이거나 없는 기록.**

```swift
(distanceMeters ?? 0) <= 0 && (strokeCount ?? 0) <= 0
```

**두 조건을 모두 요구하는 것이 요점이다.** 어느 한쪽만 보면 정상 기록이 사라진다:

- 거리만 보면 — GPS나 레인 길이를 못 잡은 개방 수역 기록이 통째로 없어진다.
- 스트로크만 보면 — 워치가 팔 동작을 못 잡은 기록이 없어진다.

둘 다일 때는 **헤엄친 흔적이 하나도 안 남은 것**이라 남길 내용이 실제로 없다. 카드에 채울
것이 거리 `-`와 스트로크 `-`뿐이다.

**시간과 칼로리는 판정에 넣지 않는다.** 둘 다 「실제로 헤엄쳤는가」를 못 가른다:

- 시간 — 잘못 시작한 것을 바로 끄지 않고 몇 분 뒤에 끄는 일이 흔하다. 6분짜리 빈 기록이
  실제로 남았다. 시간을 조건에 넣으면(예: `duration < 60`) 그것이 안 걸린다.
- 칼로리 — 그 몇 분에 워치가 5kcal쯤을 적어 넣는다. 「0kcal일 것」을 요구하면 아무것도
  안 걸리고, 소모율로 가르려 하면 임의의 문턱값이 하나 더 생긴다.

## 판정을 모델에 둔다

`SwimWorkout`의 계산 프로퍼티로 넣는다. `distanceText`·`energyText`가 이미 같은 자리에서
「보여줄 것이 있는가」를 판단하고 있고, 순수 함수라 테스트가 바로 닿는다.

```swift
extension SwimWorkout {
    /// 잘못 시작한 기록. 거리도 스트로크도 없을 때만 해당한다.
    /// 둘 다 없기를 요구해야 거리를 못 잡은 개방 수역 기록이 안 사라진다.
    var isEmptyRecord: Bool { (distanceMeters ?? 0) <= 0 && (strokeCount ?? 0) <= 0 }
}
```

## 거르는 자리는 뷰모델이다

세 후보 중 뷰모델을 고른다.

| 자리 | 왜 아닌가 |
| --- | --- |
| 뷰(`ForEach`에 `filter`) | `loadMoreIfNeeded`가 보는 `vm.workouts.last`가 화면에 없을 수 있어 **무한스크롤이 죽는다.** `showsEmptyState` 판정도 어긋난다. |
| 서비스(`HealthKitService`) | `limit`·`mayHaveMore`가 「필터 전 개수」 기준이 되어 의미가 흐려진다. 아래 커서 문제는 그대로 남는다. |
| **뷰모델** | 페이지를 받은 쪽이 커서와 목록을 **둘 다** 쥐고 있다. HealthKit 쿼리(동점 시각 무리 채우기)를 안 건드린다. |

### 필터가 페이지네이션을 두 군데서 깬다

거르기만 해서는 안 된다. 지금 커서는 화면에 남은 마지막 기록에서 나온다:

```swift
guard let cursor = workouts.last?.startDate else { return }
```

**① 걸러낸 구간을 매번 다시 읽는다.** 페이지 끝이 감춰진 기록이면 커서가 그 앞의 살아남은
기록 시각으로 물러나, 다음 페이지가 방금 버린 것들을 다시 실어 온다.

→ **커서를 목록에서 떼어낸다.** `nextCursor`를 따로 두고 **필터 전** `page.workouts.last?.startDate`로
갱신한다.

**② 한 페이지가 통째로 걸러지면 목록이 멈춘다.** 30건이 전부 감춰질 기록이면 `workouts`에
아무것도 안 붙고, **새 셀이 안 생기니 `.task`가 다시 안 뜬다.** 더 읽을 것이 남아 있는데
사용자는 스크롤로 되살릴 방법이 없다. 첫 페이지에서 이러면 「기록 없음」으로 보인다.

→ **0건 추가로 끝나면 이어서 다음 페이지를 읽는다.** `load()`와 `loadMoreIfNeeded()` 양쪽에
넣는다. 멈추는 조건은 **1건 이상 추가** 또는 **`mayHaveMore == false`**.

### 반복 횟수에 상한을 두지 않는 이유

상한에 걸려 멈추면 **목록이 안 늘어난 채 트리거도 죽어 ②와 똑같은 교착**이 된다. 상한은
문제를 안 풀고 발생 조건만 좁힌다.

상한 없이도 최악이 「이력 전체를 한 번 훑는 것」인데, 그것은 사용자가 끝까지 스크롤할 때
어차피 하는 일이다. 실수 기록이 30건 연속인 경우가 아니면 첫 회차에 끝난다.

대신 **매 회차마다 `generation` 토큰을 확인한다.** 당겨서 새로고침이 끼어들면 그 자리에서
멈춘다. 기존 코드가 늦게 온 결과를 버리는 데 쓰는 표식을 반복문 조건으로도 쓰는 것이다.

## 화면은 안 고친다

전 이력이 감출 기록뿐이면 `workouts`가 빈 채 `canLoadMore`가 false가 되어, 기존 빈 상태
(「표시할 수영 기록이 없습니다」)가 그대로 뜬다. `SwimRecordListView`는 손대지 않는다.

숨긴 건수를 알리거나 다시 펼치는 스위치는 넣지 않는다. 잘못 만든 기록은 **애초에 볼 이유가
없고**, 정말 지우려면 건강 앱이 원본이다.

## 무엇을 테스트하나

**모델 — 갈리는 네 가지**

| 기록 | 결과 |
| --- | --- |
| 55초, 거리 없음, 스트로크 없음 | 감춘다 |
| 6분, 거리 없음, 5kcal, 스트로크 없음 | 감춘다 (끄는 걸 잊은 기록) |
| 40초, 50m, 스트로크 없음 | 남긴다 (짧은 스프린트) |
| 90초, 거리 0, 스트로크 300 | 남긴다 (거리를 못 잡은 기록) |

**뷰모델 — 필터가 페이지네이션을 안 깨는가**

- 정상·감출 기록이 섞인 페이지에서 감출 것만 빠진다
- 첫 페이지가 전부 감출 기록이고 뒤에 정상 기록이 있으면, **이어 읽어서** 목록이 채워진다
- `FakeSwimFetcher.calls`의 커서가 **필터 전** 마지막 `startDate`다
- 전 이력이 감출 기록이면 `showsEmptyState`가 참이다

`FakeSwimFetcher`가 `calls`에 `(limit, cursor)`를 이미 쌓고 있어 커서 검증은 그대로 된다.
