# 사진 뷰어 — 아래로 끌어 닫기 설계

작성일: 2026-08-04
짝 저장소: 없음 — **서버 작업이 없다.** 화면 제스처뿐이다.

## 배경

전체화면 사진 뷰어(`PhotoViewerSheet`)를 닫는 길이 **왼쪽 위 ✕ 버튼 하나뿐이다.** 사진을 한
손으로 보다가 닫으려면 화면 반대편 끝까지 손을 옮겨야 한다. iOS 사진 앱을 비롯해 전체화면
이미지 뷰어는 **아래로 끌어 닫는 것이 관례**라 사용자가 먼저 그 동작을 시도한다.

## 자리가 비어 있다

`PhotoViewerSheet`의 드래그 제스처는 **확대했을 때만** 붙어 있다:

```swift
// 확대했을 때만 끌 수 있다 — 원래 크기에서 끌리면 화면이 헛돈다.
.gesture(scale > 1 ? drag : nil)
```

**원래 크기(`scale == 1`)에서는 드래그가 아예 없다.** 거기에 넣으면 확대·팬·두 번 탭과 하나도
부딪히지 않는다 — 위 주석이 비워 둔 자리를 그대로 채우는 것이다.

---

## 동작

### 언제 작동하나

**`scale == 1`일 때만.** 확대 중에는 기존 팬이 그대로 우선이다. 사진을 들여다보는 중에 닫히면
안 된다.

### 아래로 끌 때만 따라온다

위로 끄는 것은 무시한다(0으로 고정). **위로 끌리다가 아무 일도 안 일어나면 「고장인가」로
읽힌다** — 따라오게 해 놓고 안 닫는 것이 가장 나쁘다.

### 끄는 동안

- 사진이 손가락을 따라 내려가고, 내려간 만큼 조금 작아진다
- 검은 배경이 **1 → 0.55까지만** 옅어진다

**완전 투명까지 가면 안 된다.** `fullScreenCover` 뒤의 시스템 배경색이 드러나는데, 라이트
모드에서 흰색이 튀어나온다. 하한을 두는 이유가 그것이다.

### 놓았을 때

**세로 120pt 이상 내려갔거나, 아래로 빠르게 튕겼으면 닫는다.**

속도를 함께 보는 이유는 **짧고 빠른 제스처도 닫히길 기대**하기 때문이다. 거리만 보면 휙 튕기는
동작이 「안 닫히는 버그」로 느껴진다.

기준을 못 넘으면 `withAnimation(.snappy)`로 제자리에 튀어 돌아온다.

## 판정 규칙을 뷰 밖에 둔다

SwiftUI 제스처 자체는 단위 테스트가 닿지 않는다. **하지만 임계값·속도·불투명도 계산은 닿아야
한다** — 숫자 하나가 어긋나면 「가끔 안 닫힌다」로 나타나는데, 그것을 손으로만 확인하면 매번
실기기를 띄워야 한다.

```swift
enum PhotoDragDismiss {
    /// 이만큼 내려가면 닫는다.
    static let threshold: CGFloat = 120
    /// 배경이 이 아래로는 안 옅어진다.
    static let minimumBackgroundOpacity: Double = 0.55
    /// 이 속도보다 빠르게 아래로 튕기면 거리가 짧아도 닫는다.
    static let flickVelocity: CGFloat = 800

    static func shouldDismiss(translationY: CGFloat, velocityY: CGFloat) -> Bool
    static func backgroundOpacity(translationY: CGFloat) -> Double
    /// 화면에 반영할 세로 이동. **위로 끌면 0이다.**
    static func offsetY(translationY: CGFloat) -> CGFloat
}
```

`GramStepper`·`NutritionMath`와 같은 결이다 — 규칙을 뷰 밖에 두면 테스트가 닿고, 두 번째 화면이
같은 규칙을 쓰게 될 때 복사하지 않는다.

## 테스트

- 아래로 충분히 끌면 닫는다 / 조금만 끌면 안 닫는다
- **위로는 아무리 끌어도 안 닫는다** — 부호를 잘못 보면 위로 끌 때 닫힌다
- **빠르게 튕기면 거리가 짧아도 닫는다** — 거리만 보면 이 경우가 조용히 빠진다
- **배경이 하한 아래로 안 내려간다** — 많이 끌어도 0.55에서 멈춘다
- 위로 끌면 화면 이동이 0이다

---

## 범위 밖

- **위로 끌어 닫기** — 사용자가 요청한 것은 아래다. 양방향은 확대 팬과의 경계가 더 복잡해진다
- **끄는 동안 뒤 화면이 실제로 비쳐 보이게 하기** — `fullScreenCover`로는 안 된다. 커스텀
  전환이 필요하고, 얻는 것에 비해 크다
- **확대 상태에서 끝까지 팬한 뒤 이어서 닫기** — 팬과 닫기의 경계를 손끝으로 구분하기 어렵다
