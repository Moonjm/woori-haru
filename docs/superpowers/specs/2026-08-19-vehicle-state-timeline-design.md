# 차량 상태 타임라인·주행 통계 설계

**한 줄 요약.** 건강 탭의 주인공을 배터리 열화에서 **지금 상태**로 넘기고, 최근 7일을 가로 띠로 그리는 상태 타임라인을 더하고, 주행 탭 맨 위에 역대 최고 속도·이번 달·올해 주행거리 타일 셋을 놓는다.

**앞선 작업:** `docs/superpowers/specs/2026-08-17-vehicle-health-dashboard-design.md`의 1~3단계가 `main`에 있다(`60dc015` 배터리 건강 → `86b6695` 주행 인사이트 → `5cd81c4` 누적·게이지·곡선). 이 설계는 그 위에서 시작하는 **4단계**다.

**서버 설계:** `../toy-back/docs/superpowers/specs/2026-08-19-tesla-state-timeline-drive-stats-design.md`

## 배경

3단계까지 건강 탭에 쌓인 것은 대부분 **누적과 추세**다 — 잔존율, 열화 추이, 누적 주행·충전·충전비. 정작 「지금 차가 어떤 상태인가」는 배터리 %와 주행가능 거리가 표 형태로 세 줄 적혀 있을 뿐이고, `state`(온라인·오프라인·잠자는 중)는 **기준 시각 줄에 작은 글씨로 붙어 있을 뿐 화면 어디에도 제대로 나오지 않는다.**

TeslaMate의 Grafana 대시보드는 차량 상태를 시간축 띠로 그린다. 그 그림이 답하는 것은 표가 답하지 못하는 질문이다 — 「어제 얼마나 깨어 있었나」, 「밤새 충전이 언제 걸렸나」.

주행 탭도 마찬가지다. 카드 넷(온도별 전비·시간대·거리 분포·자주 가는 곳)은 「어떻게 탔나」에 답하지만 「지금까지 얼마나」에는 답하지 않는다.

## 목표

- 건강 탭을 열면 **지금 배터리와 지금 상태**가 먼저 보인다.
- 최근 7일을 어떤 상태로 보냈는지 한 장의 띠로 본다.
- 주행 탭에서 역대 최고 속도와 이번 달·올해 주행거리를 한 줄로 본다.
- 강조(진한 패널·큰 링)가 화면 순서와 어긋나지 않는다.

## 비목표

- 앱 전체를 다크로 뒤집지 않는다. 진한 패널은 **여전히 화면에서 하나뿐**이다.
- Swift Charts를 들이지 않는다. 저장소 관례대로 `Path`·`Circle().trim`·`GeometryReader`로 그린다.
- 연도별 주행거리 막대를 그리지 않는다 — 타일 셋으로 확정했다.
- 타임라인을 확대·스크롤·탭할 수 있게 만들지 않는다. 읽는 그림이다.

## 화면

### 건강 탭 순서

「현재 상태를 열화보다 위로」가 이 단계의 출발점이다. 누적도 함께 내린다 — 「지금 어떤가」를 전부 위로 올려야 순서가 한 가지 뜻을 갖는다.

```
기준 시각 · 방금            (그대로)
[미입력 3건 ›]              (그대로)

┏━ 배터리 · 상태 ━━━━━┓     ← 새 카드. 진한 패널 + 링
┗━━━━━━━━━━━━━━━━━━━┛
┌─ 최근 7일 타임라인 ─┐      ← 새 카드
┌─ 타이어 공기압 ────┐      (그대로, 위치만 이동)
┌─ 실내 · 외기 온도 ──┐      (그대로, 위치만 이동)

┌─ 누적 2×2 ────────┐      (그대로, 아래로 이동)

┌─ 배터리 건강 ──────┐      ← 링 제거, 밝은 카드로
└─ 열화 추이 차트 ────┘      (그대로)
```

### 주인공을 교체한다

`BatteryHealthCard`의 KDoc은 그 카드의 설계 의도를 이렇게 못 박아 뒀다.

> 배터리 건강 — **화면에서 유일한 진한 패널이다.** … 화면에서 가장 중요한 값 하나만 어둡게 깔아 눈이 먼저 가게 한다.

순서가 바뀌면 이 전제가 깨진다. 「눈이 먼저 가게」 만든 패널이 맨 아래로 내려가고, 새 카드에도 링을 그리면 **같은 탭에 원형 링이 둘**이 되어 「72%」와 「92%」가 안 갈린다.

그래서 **진한 패널과 큰 링을 새 카드가 물려받고, 열화 카드는 밝은 `GlassCard`로 내려간다.**

| | 지금까지 | 이 단계 이후 |
|---|---|---|
| 진한 패널 + 96pt 링 | `BatteryHealthCard` (열화) | `BatteryNowCard` (현재) |
| 밝은 `GlassCard` | 나머지 전부 | 나머지 전부 + 열화 |
| 화면 내 링 개수 | 1 | 1 |

`batteryPanelBackground()` 모디파이어와 짝 플레이스홀더는 **새 카드 쪽으로 옮긴다.** 같은 자리에 번갈아 서는 카드끼리 배경이 갈라지면 상태가 바뀔 때 색이 미묘하게 달라 보인다는 기존 주석의 이유가 그대로 새 자리에 적용된다.

### `BatteryNowCard` (새 파일)

```
┏━━━━━━━━━━━━━━━━━━━━━━━━━━┓
┃   ╭─────╮   ● 오프라인      ┃
┃  │  72%  │    3시간 12분째   ┃
┃  │ 385km │                 ┃
┃   ╰─────╯   사용 가능  70%   ┃
┃              위치       집   ┃
┗━━━━━━━━━━━━━━━━━━━━━━━━━━┛
```

- 링 96pt, 선 굵기 9 — 기존 열화 링과 같은 어휘를 그대로 물려받는다
- 링 안: `72%`(title2 heavy) 위, `385 km`(10pt semibold, 60% 불투명) 아래
- **링 색:** 50% 이상 `green300`, 20~50% `orange300`, 20% 미만 `orange500`. **문구는 붙이지 않는다** — 색만 바뀐다
- `batteryLevel`은 `Int`라 열화 링이 겪은 **표기/판정 반올림 불일치가 여기서는 생기지 않는다.** 그래도 판정은 화면에 찍는 그 값으로 한다는 규칙은 같다
- `usableBatteryLevel`은 **링에 겹치지 않는다** — 이중 링은 첫 문제(링이 둘)를 카드 안으로 옮길 뿐이다. 오른쪽 줄로 적는다
- 상태 배지는 `VehicleFormat.stateLabel`을 그대로 쓴다(다섯 값 모두 이미 한국어로 매핑돼 있다). 지속 시간은 `stateSince`로 낸다
- **`odometer` 줄을 뺀다** — 지금 `batteryCard`에 있는 「주행거리」는 누적 카드의 「주행」 타일과 **같은 값**이다. 링 카드로 바뀌면서 중복을 지운다

값이 없거나 못 받았을 때는 **같은 자리·같은 진한 패널**로 선다. 첫 화면의 주인공이 사라지면 화면이 무너져 보인다는 이유는 자리가 바뀌어도 같다.

### `BatteryHealthCard` 변경

링을 지우고 `GlassCard`로 내린다. 네 값은 그대로 남긴다.

```
┌─ 배터리 건강 ──────────┐
│ 잔존율          92%    │  ← 색만 유지
│ 주행가능      525 km    │
│ 용량        71.6 kWh    │
│ 줄어든 거리    43 km    │
└───────────────────────┘
```

잔존율 숫자에 **기존 링 색 규칙을 그대로 옮긴다** — 90% 이상 초록, 80~90% 노랑, 80% 미만 주황, 그리고 **`VehicleMath.rounded`로 반올림한 값으로 판정한다.** 원값으로 판정하면 `[89.5, 90)`이 "90%"로 보이면서 색은 노랑이 되는 불일치가 링에서 숫자로 자리만 옮겨 살아남는다.

접근성 라벨은 링이 없어져도 **네 값을 모두 이어 붙인다.** `.combine`이 자식을 묶기만 하고 읽어 주지는 않는다는 기존 주석의 함정이 그대로다.

### `StateTimelineChart` (새 파일)

```
┌─ 최근 7일 ─────────────────────────┐
│ 8/13  ██▓▓▓▓░░░░░░░░░░░░░░▓▓░░      │
│ 8/14  ░░░░░░░░▓▓▒▒▒░░░░░░░░░░░      │
│ 8/15  ░░░░░░░░░░░░░░░░░░░░░░░░      │
│ 8/16  ░░░░▓▓▒▒░░░░░░░░▒▒▓▓░░░░      │
│ 8/17  ░░░░░░░░░░░░░░░░░░░░░░░░      │
│ 8/18  ░░░░░░▓▓░░░░░░▒▒▒▒░░░░░░      │
│ 8/19  ░░░░░░░░                      │
│       0시      6      12    18   24 │
│                                     │
│ ▓온라인 ░오프라인 ▨잠자는중 ▒주행 █충전 │
└─────────────────────────────────────┘
```

- 7행, 행 높이 14pt, 행 간격 3pt. 왼쪽 날짜 라벨 폭 32pt
- **위가 가장 오래된 날, 아래가 오늘.** 아래로 읽어 내려가면 지금에 닿는다
- **오늘 행은 지금 이후가 빈칸이다** — 아직 오지 않은 시간을 색으로 칠하지 않는다
- 겹치는 순서: **상태를 깔고 → 주행 → 충전**을 덧칠한다. 주행과 충전이 동시에 열리는 일은 없다
- 색: `asleep` `slate200` · `offline` `slate300` · `online` `blue300` · 주행 `blue600` · 충전 `green600` (모두 기존 토큰)
- 실측상 최근 7일은 **오프라인이 131시간(78%)**이라 화면 대부분이 회색이다. 그게 사실이므로 그대로 그린다
- `asleep`은 최근 7일 표본에 0건이지만 2026년에 월 1~4건씩 있었다. **범례에서 빼지 않는다**

**VoiceOver**는 행마다 하루를 읽는다 — 「8월 13일, 온라인 4시간, 주행 2회, 충전 1회」. 2단계 히트맵이 행 단위 라벨을 붙인 것과 같은 방식이다. 개별 구간에는 라벨을 붙이지 않는다(168개를 하나씩 읽게 만들 이유가 없다).

### 주행 탭 — `DriveStatsCard` (새 파일)

기존 카드 넷 **위에** 타일 줄 하나를 놓는다. 다섯째 차트를 더하지 않는다.

```
┌────────┬────────┬─────────┐
│  138   │ 1,331  │ 13,440  │
│  km/h  │   km   │   km    │
│ 역대 최고 │ 이번 달 │  올해   │
└────────┴────────┴─────────┘
```

- 기존 `tile(_:_:)` 패턴(값 위·라벨 아래, `slate100` 배경, 12pt 라운드)을 그대로 쓴다
- **라벨이 「최고 속도」가 아니라 「역대 최고」다.** 이 값만 `months` 창을 따르지 않으므로 옆 두 칸과 범위가 다름을 글자로 드러낸다
- 거리는 `VehicleFormat.odometer`와 같은 규칙(천단위 구분, 정수)으로 찍는다
- 속도는 새 포매터 `VehicleFormat.speed(_:)` → `"138 km/h"`, nil이면 `ChargeFormat.placeholder`

## 서버 API

계약 전문은 `toy-back` 설계 문서에 있다. 앱이 의존하는 부분만 옮겨 적는다.

```
GET /tesla/state-timeline?days=7
{ "data": { "days": 7, "from": "2026-08-13T00:00:00", "to": "2026-08-19T12:34:56",
            "states":  [ { "state": "offline", "from": "…", "to": "…" } ],
            "drives":  [ { "from": "…", "to": "…" } ],
            "charges": [ { "from": "…", "to": "…" } ] } }
```

- **세 배열은 겹친 채로 온다.** 서버가 하나의 띠로 합치지 않는다 — 겹칠 때 무엇이 이기는지는 화면이 정한다
- 시각은 **KST 벽시계**다. 창은 서버가 **KST 자정에 맞춰** 잘라 주므로 `days=7`이면 온전한 6일 + 오늘 부분 = 7행이 된다
- 구간은 서버가 창에 맞춰 이미 잘라 보낸다. 앱이 다시 자르지 않는다
- 유령 세션(마감되지 않은 옛 주행·충전)은 서버가 24시간 룰로 걸러 낸다. **앱은 이 필터를 다시 만들지 않는다**

`/tesla/drive-insights`에 셋이 붙는다.

```swift
let maxSpeedKmh: Int?           // 역대 최고. months 창과 무관
let monthDistanceKm: Decimal    // 이번 달, KST 경계. 없으면 0
let yearDistanceKm: Decimal     // 올해, KST 경계. 없으면 0
```

**`maxSpeedAt`은 없다.** 실측 138 km/h가 최소 3건 동률이라(2025-09-13 · 2025-03-22 · 2024-03-09) 「그날 기록했다」고 말할 수 없다.

## 계산 — `StateTimelineMath`

화면이 하는 유일한 계산이고, 순수 함수라 테스트가 붙는다.

```swift
enum TimelineKind { case asleep, offline, online, driving, charging }

struct TimelineBar: Equatable {
    let dayIndex: Int   // 0 = from의 날, days-1 = 오늘
    let start: Double   // 그 행 안에서 0.0 ~ 1.0
    let end: Double
    let kind: TimelineKind
}

static func bars(_ response: StateTimelineResponse) -> [TimelineBar]
```

하는 일 셋:

1. **자정을 넘는 구간을 날짜 행으로 쪼갠다.** 오프라인 밤샘 하나가 두 행이 된다
2. **`from`·`to` 밖을 자른다.** 서버가 이미 잘라 주지만 계약이 깨져도 화면이 무너지지 않게 한 번 더 막는다
3. **`kind` 순으로 정렬한다** — 상태 → 주행 → 충전. 그리는 쪽이 순서를 신경 쓰지 않아도 되게 한다

### 최소 폭을 두지 않는다

짧은 구간은 화면에서 사라진다. 폭 393pt에서 24시간을 그리면 1시간 ≈ 15pt이므로 2분짜리 구간은 0.5pt다.

**실측이 이 걱정을 거의 지웠다.** 최근 7일 상태 구간 145개 중 2분 미만은 **2개**뿐이고(둘 다 오프라인), 온라인은 최소 11.2분·중앙 12.2분이다. 주행 22건은 최소 1분·중앙 18분이다.

여기에 바닥값을 깔면 **짧은 구간이 실제보다 길어 보이는 띠**가 된다. 2단계에서 nil 전비 막대에 3pt 바닥을 깔았다가 되돌린 것과 같은 함정이고, 충전 행 게이지의 「한쪽만으로 그린 막대는 거짓말이다」와 같은 규칙이다. **렌더링 하한으로 1픽셀만 둔다** — 그건 거짓말이 아니라 화면의 물리적 하한이다.

## 뷰모델

이 저장소는 **엔드포인트 하나에 뷰모델 하나**다(`VehicleHealthViewModel`·`VehicleStatusViewModel`·`ChargeTotalsViewModel`·`VehicleDriveViewModel`). 타임라인도 `StateTimelineViewModel`을 새로 둔다. 건강 탭이 뷰모델 넷을 받게 되지만 규칙은 그대로다.

```swift
@MainActor @Observable
final class StateTimelineViewModel {
    private(set) var timeline: StateTimelineResponse?
    var errorMessage: String?
    func load() async   // 매번 reload()를 부른다
    func reload() async // generation 토큰, 실패해도 있던 값을 지우지 않는다
}
```

**누적(`ChargeTotalsViewModel`)과 반대로 캐시하지 않는다.** 「최근 7일」은 창이 계속 움직이므로 탭에 들어올 때마다 새로 받아야 한다. 누적은 전 기간 집계라 한 번만 받는 것이 맞았지만 여기서는 틀린다.

당겨서 새로고침에 `timelineViewModel.reload()`를 더한다(지금 넷 → 다섯).

주행 통계는 **뷰모델을 만들지 않는다** — 기존 `/tesla/drive-insights` 응답에 필드가 붙는 것뿐이라 `VehicleDriveViewModel`이 그대로 나른다.

## 경계와 오류

| 상황 | 화면 |
|---|---|
| 타임라인 실패 · 값 있음 | 있던 띠를 그대로 두고 **한 줄 배너**만 띄운다 |
| 타임라인 실패 · 값 없음 | 카드 자리에 안내 + 「다시 시도」 |
| 구간이 하나도 없음 | 「최근 7일 기록이 없어요」. 실패와 다르게 그린다 |
| 배터리 값 없음 | 진한 패널 플레이스홀더가 **같은 자리**에 선다 |
| `maxSpeedKmh`가 nil | 그 타일만 `—`. 옆 두 칸은 그대로 그린다 |
| 이번 달·올해 거리가 0 | **`—`가 아니라 `0 km`**다. 서버가 0을 내는 이유가 그것이다 |

「값이 있는 새로고침 실패는 조용히 있던 값을 보여준다」는 규칙은 1~3단계에서 세 번 고쳐 가며 정착한 것이다. 새 카드도 같은 규칙을 따른다 — **오류 확인이 값 확인보다 먼저 오면 안 된다.**

## 테스트

Swift Testing(`import Testing`). 뷰는 테스트하지 않고 계산과 뷰모델만 본다.

**`StateTimelineMath.bars`**

- 하루 안에 든 구간 하나가 그 행의 올바른 비율로 나온다
- 자정을 넘는 구간이 **두 행**으로 쪼개진다
- 이틀을 통째로 덮는 구간이 **세 행**(부분·전체·부분)으로 쪼개진다
- `from` 이전·`to` 이후로 삐져나온 구간이 잘린다
- 오늘 행이 `to`에서 끝난다 — 그 뒤는 막대가 없다
- 빈 입력이 빈 배열을 낸다
- 결과가 상태 → 주행 → 충전 순으로 정렬된다

**`VehicleFormat.speed`**

- `138` → `"138 km/h"`, `nil` → placeholder

**`StateTimelineViewModel`**

- 실패해도 있던 값을 지우지 않는다
- 늦게 도착한 옛 응답이 새 값을 덮어쓰지 않는다(generation 토큰)
- `load()`가 **매번** 서버를 부른다 — 누적 뷰모델과 달리 캐시 가드가 없다

**`VehicleFormat`의 잔존율 색 판정**

- `89.5`가 `"90%"`로 찍히고 색도 90% 구간(초록)으로 판정된다 — 링에서 숫자로 옮긴 뒤에도 표기와 판정이 갈리지 않는지 본다

## 확정한 결정 요약

| 결정 | 이유 |
|---|---|
| 진한 패널·큰 링을 현재 상태가 물려받는다 | 순서를 바꾸면 강조도 따라가야 한다. 링이 둘이면 안 갈린다 |
| 서버가 세 배열을 겹친 채로 낸다 | 구간 산술을 서버에 만들지 않는다. 겹침 규칙은 화면의 것이다 |
| 최소 폭을 두지 않는다 | 바닥값은 짧은 구간을 길게 보이게 하는 거짓말이다. 실측상 2분 미만은 145개 중 2개뿐 |
| 「역대 최고」라는 라벨 | 이 값만 `months` 창을 따르지 않는다 |
| `maxSpeedAt`을 두지 않는다 | 138 km/h가 최소 3건 동률이라 「그날」이 없다 |
| 월·연 거리는 0을 낸다 | 기간이 못박힌 합계다. nil로 두면 매달 1일 새벽마다 `—`가 뜬다 |
| 타임라인은 캐시하지 않는다 | 창이 계속 움직인다. 누적과 반대다 |
| `odometer` 줄을 뺀다 | 누적 카드의 「주행」 타일과 같은 값이다 |
