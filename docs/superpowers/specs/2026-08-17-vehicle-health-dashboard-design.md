# 차량 건강 대시보드 설계

**한 줄 요약.** 차량 미니앱의 첫 화면을 배터리 건강 대시보드로 바꾸고, 열화를 눈으로 볼 수 있게 한다.

## 배경

차량 미니앱은 `요약`·`상태` 두 탭이다. 요약은 그 달 충전 금액을 다루는 화면이고, 상태는 마지막으로 받은 값을 표 형태로 늘어놓은 화면이다. 상태 탭에는 **지금 이 순간의 값만** 있다 — 배터리 82%, 주행가능 430km. 이 숫자들은 어제와 비교되지 않으므로, 열어 봐야 알게 되는 것이 없다.

정작 전기차를 오래 타면서 궁금해지는 것은 **배터리가 얼마나 줄었나**인데, 그 답은 우리가 이미 가진 데이터에 들어 있다. TeslaMate의 `charging_processes`에는 충전이 끝난 시점의 배터리 %와 주행가능거리가 매 건 남는다. 이 둘을 나누면 그날의 만충 환산 주행거리가 나오고, 그것을 시간축에 늘어놓으면 열화 곡선이 된다.

### 기준선을 무엇으로 둘 것인가

「신차 대비 몇 %」를 내려면 신차 값이 필요한데, **TeslaMate에는 제원표가 없다**(`cars`에 있는 것은 `model`·`trim_badging`·`efficiency`뿐이다). 상수를 우리가 심어야 하고, 후보가 둘이었다.

- EPA 인증: 353마일 = **568km**
- 국내 환경부 인증(상온 복합): **528km**

실측으로 갈랐다. 2026-08-15 충전 한 건이 `17% → 99%`, 주행가능거리 `90km → 520km`, 충전량 `58.7kWh`였다.

| 지표 | 실측 100% 환산 | 568km 기준 | 528km 기준 |
|---|---|---|---|
| 주행가능거리 | 약 525km | 잔존 92.4% | 잔존 99.4% |
| 사용 가능 용량 | 약 71.6kWh | — | — |

용량 쪽이 답을 준다. 신차 사용 가능분 약 78.5kWh 대비 71.6kWh면 **잔존 91%**다. 주행거리로 낸 92.4%와 같은 자리이므로, TeslaMate가 저장하는 주행가능거리는 **EPA 기준**이다. 528km를 기준선으로 잡았다면 5년 탄 차의 열화가 0.6%로 표시될 뻔했다.

**대상 차량은 2021년 9월 출고 모델 3 롱 레인지(AWD)다. 신차 기준선은 568km / 78.5kWh로 고정한다.**

## 목표

- 첫 화면에서 배터리 잔존율과 열화를 한눈에 본다.
- 열화가 시간에 따라 어떻게 움직였는지 추이로 본다.
- 타이어 공기압을 「읽는 숫자」가 아니라 「확인하는 값」으로 바꾼다.
- 충전 금액 입력 경로는 화면이 바뀌어도 그대로 살아 있다.

## 비목표

- **실시간 표시.** 충전 중 kW, 주행 중 상태 같은 것은 넣지 않는다. 진행 중인 충전은 지금도 서버가 걸러 내려주지 않으며, 그 정책을 이번에 건드리지 않는다.
- **주행(drives) 기록.** 경로 지도·속도 차트·시간대 히트맵은 데이터는 있지만 서버 API와 화면을 통째로 새로 여는 일이라 이번 범위 밖이다.
- **금액 입력 기능 변경.** 큐 화면과 상세 「금액 수정」의 코드는 손대지 않는다. 건강 화면에 배지를 하나 더 다는 것은 **진입점 추가**이지 입력 경로 변경이 아니다.
- **여러 대 차량.** 기준선을 앱 상수 한 곳에 둔다. 차를 바꾸면 그 줄을 고친다.

## 화면

### 탭 순서

`건강`(기존 상태 탭) · `요약` 순으로 바꾼다. 미니앱을 열면 건강 화면이 먼저 뜬다.

**금액 입력이 멀어지지 않게 한다.** 요약 탭에만 있던 「금액 미등록 N건」 배지를 건강 화면 위쪽에도 둔다. 눌렀을 때 열리는 곳은 지금과 같은 큐 화면이다. 이 앱에서 사람이 실제로 손을 쓰는 일은 금액을 채워 넣는 것 하나뿐이므로, 첫 화면이 바뀌어도 그 일이 한 번의 탭 안에 있어야 한다.

### 배터리 건강 카드 — 유일한 진한 패널

이 카드만 어두운 그라데이션 패널이고 나머지는 기존 `GlassCard`다. 앱 전체를 다크로 뒤집지 않는다 — 지금 유리 토큰은 밝은 배경을 전제로 만들어졌고, 우리하루의 다른 미니앱과 결도 어긋난다. 대신 **화면에서 가장 중요한 값 하나만 어둡게 깔아** 눈이 먼저 가게 한다.

- 요약 탭 히어로(초록→파랑)와 **다른 색을 쓴다.** 같은 색을 두 화면 첫 카드에 쓰면 어느 화면인지 헷갈린다. 여기는 어두운 남색 계열 바탕에 잔존율 링만 초록으로 둔다.
- 잔존율은 링(`Circle().trim`)으로 그린다. Swift Charts를 들이지 않는 저장소 관례를 따른다.
- 잔존율이 낮아지면 링 색이 바뀐다: 90% 이상 초록, 80~90% 노랑, 80% 미만 주황. **경고 문구는 넣지 않는다** — 열화는 고장이 아니다.
- 숫자는 `monospacedDigit`, 단위는 숫자보다 작은 글자로 붙인다.

### 열화 추이 차트

월별 만충 환산 주행거리를 선으로 잇는다. 손으로 그린다(`Path`).

- **y축을 0에서 시작하지 않는다.** 0부터 그리면 몇 %의 변화가 선 굵기에 묻힌다. 대신 **신차 기준선 568km를 점선으로 함께 그려** 무엇과 비교하는 값인지 화면 안에 남긴다.
- 표본이 없는 달은 **선을 잇지 않고 끊는다.** 없는 값을 직선으로 메우면 그 달에도 측정한 것처럼 보인다.
- 최근 24개월까지 그린다. 그보다 오래된 표본은 서버가 주더라도 그리지 않는다.
- 점을 누르면 그 달 값이 위쪽 콜아웃에 뜬다. `VehicleTrendChart`의 방식과 같다.

### 타이어 공기압

지금은 FL·FR·RL·RR 숫자 네 개라, 그 값이 정상인지는 사람이 판단해야 한다. 차 도형 위 네 모서리에 psi를 얹고, **권장값에서 벗어난 바퀴만 색을 바꾼다.**

- 권장 42psi, 정상 범위 38~46psi. 상수로 둔다.
- 네 바퀴가 모두 정상이면 카드 아래 `✓ 네 바퀴 모두 정상`을, 아니면 벗어난 바퀴 이름을 적는다.
- 값이 없는 바퀴는 `—`다. 0psi가 아니다.
- 표기는 지금대로 **psi만** 낸다(`VehicleFormat.pressurePsi`).

## 계산

나눗셈은 지금 관례대로 앱의 `VehicleMath`에서 한다. 서버는 표본만 낸다 — 분모가 0이거나 nil일 때의 처리를 서버가 정해 버리면 화면이 그것을 따라야 한다.

### 만충 환산 주행거리

```
fullRangeKm = endRatedRangeKm ÷ endBatteryLevel × 100
```

- **종료 배터리 80% 이상인 충전만** 표본으로 쓴다. 낮은 SoC에서 환산하면 오차가 커진다.
- 한 달에 표본이 여럿이면 **중앙값**을 쓴다. 급속 직후 값이 튀어도 평균처럼 끌려가지 않는다.

### 사용 가능 용량

```
capacityKwh = chargeEnergyAddedKwh ÷ (endBatteryLevel − startBatteryLevel) × 100
```

- **SoC 변화폭 40%p 이상인 충전만** 표본으로 쓴다. 짧은 보충은 오차가 크다.
- 월별 중앙값을 쓴다. 표본이 없는 달은 nil이다.

### 잔존율·열화

```
잔존율 = 최근 만충 환산 ÷ 568
열화   = 1 − 잔존율
```

용량 쪽 잔존율도 같은 방식으로 78.5kWh 기준으로 낸다. **두 값이 어긋나면 주행거리 쪽을 큰 숫자로 낸다** — 화면 제목이 「배터리 건강」이고 사람이 체감하는 것은 갈 수 있는 거리다.

## 서버 API

```
GET /tesla/battery-health

{
  "samples": [
    { "yearMonth": "2026-08", "fullRangeKm": 525.3, "capacityKwh": 71.6, "sampleCount": 3 },
    { "yearMonth": "2026-07", "fullRangeKm": 527.1, "capacityKwh": null,  "sampleCount": 1 }
  ]
}
```

- 표본 규칙(80% 이상 / 40%p 이상)은 서버 쿼리에서 거른다. 앱이 전 건을 받아 거르지 않는다.
- 표본이 없는 달은 **배열에서 빠진다.** 자리를 지키지 않는다 — 열화 추이는 월 경계가 의미를 갖는 값이 아니라, 없는 달은 없는 대로 두면 된다.
- 신차 기준선(568km / 78.5kWh)은 응답에 넣지 않는다. **앱 상수**다. 서버가 차종을 알 이유가 없다.

## 엣지 케이스

- **표본이 하나도 없다** — 카드 자리에 「아직 잴 만한 충전이 없어요 · 80% 이상 충전하면 값이 쌓여요」를 낸다. 「기록 없음」과 「못 받음」을 구분하는 지금 관례를 따른다.
- **표본이 한 달치뿐** — 카드는 그린다. 추이 차트는 점 하나이므로 선 대신 점만 찍고, 「값이 쌓이면 추이가 보여요」를 함께 낸다.
- **잔존율이 100%를 넘는다** — 있을 수 있다(냉간·BMS 재보정). 100%로 자르지 않고 그대로 낸다. 대신 열화는 음수로 쓰지 않고 `0%`로 낸다.
- **응답 실패** — 건강 카드만 오류 자리로 바뀌고 아래 상태 카드들은 그대로 보인다. 두 API는 서로 독립이다.

## 테스트

`VehicleMath`에 붙는 계산부터 단위 테스트로 쓴다.

- 만충 환산: 정상값 / `endBatteryLevel == 0` / nil
- 용량 추정: 정상값 / ΔSoC == 0 / 시작 > 종료
- 잔존율: 정상값 / 100% 초과 / 기준선 대비 음수 열화
- 중앙값: 표본 짝수·홀수 / 표본 없음
- 공기압 판정: 범위 안 / 위 / 아래 / nil

화면 쪽은 **탭 순서를 바꾼 뒤에도 금액 입력 경로가 살아 있는지**를 실기로 확인한다 — 배지 → 큐 → 저장 → 배지 수 갱신.

## 열어 둔 것

- **누적 스탯 타일**(누적 주행·누적 충전·평균 전비·주유비 대비 절감액)과 **온도별 전비 차트**는 다음 단계로 미룬다. 첫 화면이 산만해지는 것보다 배터리 건강 하나가 또렷한 편이 낫다.
- 충전 목록 행의 배터리 게이지(`63% → 80%` 시각화)는 요약 탭 쪽 개선이라 이 설계에 넣지 않는다.
